# CRM 고객관리 템플릿 빌더 — 제품 방향 (고정)

이 문서는 **고객관리(CRM) 동적 템플릿 빌더**와 그 주변 영역에 대한 제품 스코프를 한 곳에 고정하기 위한 것이다.  
배포·브랜치 규칙은 루트 `AGENTS.md`를 따르고, **기능·아키텍처 우선순위는 이 문서를 단일 기준**으로 삼는다.

---

## 1. 1차 목표

현재 **1차 목표는 고객관리 템플릿 빌더를 완성하는 것**이다.  
다른 전사 과제(PDF 자동화, 전자문서 발송 등)가 있더라도, **이 1차 목표를 약화하거나 희석하는 방향으로 범위를 확장하지 않는다.**

---

## 2. 관리자 구성 능력

**관리자**가 UI에서 **업종별**로 다음을 구성할 수 있어야 한다.

- 고객 **등록** 화면
- 고객 **목록** 화면
- 고객 **상세** 화면
- 고객 정보 **수정** 화면

업종은 산업 도메인 라벨로 표현될 수 있으나, 구현은 **단일 동적 빌더**로 수렴한다(아래 §5 참조).

---

## 3. 공통 빌더의 핵심 데이터

**공통 빌더**의 구조적 핵심은 아래 요소를 일관되게 다루는 것이다.

| 영역 | 설명 |
|---|---|
| `formFields` | 등록·수정 폼 필드 정의 |
| `listColumns` | 목록 컬럼 정의 |
| `detailTabs` | 상세 탭·섹션 구성 |
| `options` | 선택형 필드 옵션 등 |
| `required` | 필수 여부 |
| `type` | 저장·검증용 타입 |
| `displayType` | 화면 표시 방식 |
| 순서 | 필드·탭·컬럼 등의 **정렬·가시 순서** |
| 상태 | `draft` / `active` / `archived` 등 생명주기 |
| tenant 연결 | 어떤 테넌트가 어떤 템플릿을 쓰는지 |

이 목록은 **스키마 필드 이름을 한정하는 고정 API 명세**가 아니라, **빌더가 책임져야 할 관심사의 체크리스트**로 본다. 구현 세부는 코드와 DB 스키마에 따르되, **원칙은 동일하게 유지**한다.

---

## 4. 업종 전용 페이지·전용 TS 템플릿 누적 금지

`government` / `liquor` / `gym` 등 **업종 코드마다 전용 페이지**를 계속 추가하지 않는다.  
마찬가지로 **업종별 전용 TypeScript 템플릿 파일**을 늘리는 패턴도 **새 작업의 기본 선택지로 쓰지 않는다.**

---

## 5. 업종 차이는 DB 동적 템플릿으로 흡수

**업종별(또는 고객군별) 차이**는 소스 코드에 분기·페이지를 쌓지 않고, **DB에 저장된 동적 템플릿 데이터**로 흡수한다.  
빌더·런타임은 **동일한 엔진**으로 읽고 렌더링한다.

---

## 6. 고객관리 빌더에 포함하지 않는 것

아래는 **고객관리 템플릿 빌더의 범위에 넣지 않는다.**

- PDF **좌표 편집**
- **문서 자동화** 전반(좌표·양식·생성 파이프라인을 빌더 UI에 통합하는 형태)
- **전자문서 발송** 기능

즉, 빌더는 **고객 데이터와 화면 구성**에 집중하고, 문서/PDF/발송 제품을 한 화면에 끌어들이지 않는다.

---

## 7. PDF 자동화는 별도 단독 서비스

**PDF 자동화**(양식 작성, 좌표 매핑, 생성 워크플로 등)는 이후 **별도의 단독 서비스**로 설계·구현한다.

---

## 8. 전자문서 발송도 별도 단독 서비스

**전자문서 발송**은 이후 **별도의 단독 서비스**로 설계·구현한다.  
고객관리 빌더 내부에 발송대장·연동 UI를 풀어 넣는 것은 **범위 외**로 둔다.

---

## 9. 향후 연결을 막지 않을 것

고객관리 빌더는 §6~8과 같이 **당장 통합하지 않지만**, 나중에 PDF·전자문서 서비스와 **식별자·필드 주소 체계**로 연결할 수 있도록 하는 것을 **금지하지 않는다.**

- 필드·엔티티·버전을 가리키는 **안정적인 키/경로** 설계
- 외부 서비스가 참조할 수 있는 **참조 가능한 주소 체계**

위와 같은 **연결 가능성**은 설계 시 **배제하지 않는다**(단, §6 범위 확장과 혼동하지 말 것).

---

## 10. 현재 작업 범위(이 에픽의 완료 정의)

지금 손대는 범위는 **고객관리 빌더**에 한정하며, 최소한 다음까지를 목표로 한다.

- 템플릿 **저장**
- 템플릿 **복원**(로드·적용)
- **검증**(관리자 입력·스키마 일관성 등)
- **테넌트 연결**(어떤 고객사가 어떤 템플릿을 쓰는지)
- 위 설정이 **일반 사용자·설계사 화면**에 반영되는 것

PDF·전자문서 단독 서비스의 구현·배포는 **이 완료 정의에 포함하지 않는다.**

---

## 요약 한 줄

**1차는 동적 CRM 템플릿 빌더만 끝까지 완성하고, PDF·전자문서는 분리된 서비스로 두며, 업종 분기는 코드가 아니라 DB 템플릿으로 흡수한다.**
